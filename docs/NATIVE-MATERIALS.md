## 1.91.85 补漏与动态证据

1.91.84 的冻结一级页两张概览主卡片没有语义标记，且背景被 RippleDrawable 包装，扫描未接入材质。因此页面存在新材质组件并不足以证明主要卡片完成接入。

流体组件移除轮廓亮线主导的表现，使用多团融合密度场、曲面法线、厚度光照和连续颜色迁移。这是具有体积明暗的程序化表面，仍不是三维物理流体求解器。

动态采集使用 PixelCopy 读取正式 APK 实际窗口，保留每帧时间戳。测试中的按住、拖动、取消事件经过真实 Activity 分发；使用取消结束，避免激活卡片点击或更改业务规则。它验证材质交互和恢复，不等同于完整的实际手指操作、快速滑动或导航转场验收。

设备系统 screenrecord 在编码器初始化等待 hwservicemanager，未生成有效视频。低频 ADB 截屏只能达到约每秒 1 帧，不能用于动效验收，后续改为上述窗口连续帧采集。采集帧率单独记录，不能代替实际渲染性能测量。

## 1.91.84 接入记录

两套材质通过原有 StyleManager / ThemedActivity 附着到业务页面，不复制 Activity、业务状态、规则或导航。简约、空间风格保持原实现。

## 背景与组件

`Ui.page()` 标记页面背景来源；打卡页额外提供原有自选背景 ImageView 和压色层。材质只采样这些显式背景视图，不截取表单、文字、应用名单等业务内容。不替换背景图，也不铺设新的全屏视觉覆盖层。尚无背景标记的旧页面使用现有窗口底色作为光照环境。

`NativeComponentLayer` 对标准卡片、带背景的可点击按钮、输入框、标签添加绘制包装。保留原背景、圆角、语义类别颜色、padding、原尺寸、控件内容和事件监听器。页面自行更新背景时重新绑定；释放时只恢复仍由本层持有的背景，不覆盖页面的新状态。

- Glass：对原有背景纹理进行曲面采样偏移和分色采样，叠加边缘厚度、局部凹陷和释放波纹。
- Fluid：由密度场与梯度光照生成组件内部运动，同时混入原背景色；手势扰动局部密度场。
- Fluid 在原生暖色背景上为浅色文字加柔和深色轮廓光，只改变文字绘制；切换风格或退出页面时恢复原阴影参数。
- 两种材质程序由各自风格模块独立持有，共享层负责绑定、生命周期和坐标。
- 原生导航已有独立 painter 接口，继续使用现有导航实现。系统弹窗和无背景的自绘图标未统一替换成实验室组件。

## 手势和性能

ThemedActivity 提供只读触点观察。打卡页在自己处理拖动前调用同一观察入口，重复转发到父类会去重。材质不能消费事件或修改卡片完成/取消/切换规则。

每页共享一个材质程序和至多 384×896 的背景纹理；编译异步执行。只使实际可见的组件失效，不给每个控件启动独立动画循环。沿用现有帧测量与 EffectQualityManager 降档策略。LOW 和减少动态效果不持有持续帧循环或 GPU 程序，保留原生控件和静态材质。页面退出或切换释放时钟、监听、纹理和材质引用。

Java 8 / API 24 兼容构建同样使用该实现；API 33 以下保留轻量降级。原生打包脚本加入两个材质程序，避免只有 Compose 构建包含资源。
